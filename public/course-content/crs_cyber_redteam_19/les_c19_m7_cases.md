## Purple teaming and ATT&CK-based coverage measurement Context: organisations increasingly run purple-team exercises and continuous security validation to measure detection coverage against MITRE ATT&CK: red emulates techniques, blue measures detections, and the two collaborate to close gaps and track coverage over time. This threat-informed, collaborative model - rather than adversarial, score-based red teaming - is widely promoted because it directly improves detection and is repeatable [C19-M07-R1][C19-M07-R2]. Why it matters for this module: it confirms that the valuable output is measured, prioritised detection improvement mapped to ATT&CK - exactly the gap analysis and retest list the lab produces. Lessons: collaborate; measure coverage against ATT&CK; close gaps and re-test; track coverage continuously.



## (FICTIONAL TEACHING SCENARIO): The 4-of-7 that became 7-of-7 Context: a fictional retailer, Malabar Mart, runs a purple-team exercise using the seven-technique plan. What happened: the gap analysis (purple.py) showed 4/7 detected and three gaps - Account Discovery, Use Alternate Authentication Material, and Data from Local System - each with the telemetry and detection needed. Red and blue, sharing the ATT&CK plan, diagnosed the gaps as missing directory, authentication-correlation and file telemetry. Response: the blue team engineered the three detections, and the red team re-emulated the same techniques in the isolated range; all three now fired, raising coverage to 7/7. The team adopted continuous re-emulation of the key techniques to catch regressions. Lessons: gap analysis gives a concrete backlog; collaboration diagnoses the cause; retesting proves the fix; make it continuous.
