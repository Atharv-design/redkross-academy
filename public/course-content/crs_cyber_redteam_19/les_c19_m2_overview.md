## About this module

Adversary emulation means reproducing the BEHAVIOUR of a realistic threat - the techniques a relevant adversary would use - to test whether an organisation can detect and respond. This module covers threat-informed planning, the MITRE ATT&CK framework, technique selection, and the simulation boundaries that keep emulation safe. You will build and validate an emulation plan in which every step names an ATT&CK technique, a target in scope, a safety boundary and the detection it should produce.

## Why it matters

Emulating a RELEVANT adversary - rather than running arbitrary attacks - makes an engagement meaningful: it tests the defences that matter against the threats the organisation actually faces, and it produces findings mapped to a shared language (ATT&CK) that the blue team can act on. Threat-informed planning and clear simulation boundaries are what separate a disciplined emulation from reckless activity. This is the planning core of red teaming.

## Where it is used

Adversary emulation and threat-informed defence programmes; ATT&CK-based red team planning; emulation plans (such as those published by MITRE's Center for Threat- Informed Defense); and purple-team exercise design.

## Learning objectives

1. Explain adversary emulation and how it differs from arbitrary testing.
2. Explain threat-informed planning.
3. Explain the MITRE ATT&CK framework and its use in planning.
4. Select techniques for a threat profile and map them to detections.
5. Define simulation boundaries and safety controls per step.
6. Validate an emulation plan before running it.
