## Indirect prompt injection described, February 2023 ------------------------------------------------------------------------- Context: "Not what you've signed up for: Compromising Real-World LLM-Integrated Applications with Indirect Prompt Injection" by K. Greshake, S. Abdelnabi, S. Mishra, C. Endres, T. Holz and M. Fritz was first submitted to arXiv on 23 February 2023. It argues that indirect prompt injection can "enable adversaries to remotely (without a direct interface) exploit LLM-integrated applications" by planting instructions in data the application retrieves [C18-M02-R1]. Architecture lessons: - Retrieval and tool results are input channels; treat them as untrusted. - The boundary between "data" and "instructions" cannot be enforced by the model alone; enforce it with retrieval controls, tool policies and output handling. - Threat models must include content authors (web pages, documents, e-mails), not only users.



## (FICTIONAL TEACHING SCENARIO): The shared index --------------------------------------------------------------------- This scenario is fictional. Banyan's internal HR assistant indexed every SharePoint site it could read with a service account. An employee asking about leave rules received a summary that quoted a salary spreadsheet. The retrieval layer had no per-user filtering. The fix: index with document ACLs, filter by the requesting user's groups before ranking, and exclude restricted sites from the index entirely.
