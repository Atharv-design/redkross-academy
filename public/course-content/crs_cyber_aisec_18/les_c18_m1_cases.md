## Chatbot data exposure, March 2023 - classic bugs in an AI service ------------------------------------------------------------------------ Context: Help Net Security reported on 27 March 2023 that OpenAI had confirmed a vulnerability in the redis-py open-source library was at the root of a ChatGPT data leak the previous week. Some users could see the titles of other users' conversations. During a nine-hour window on 20 March 2023, another user may have seen a subscriber's billing information on their own "Manage Subscription" page; OpenAI notified 1.2% of ChatGPT Plus subscribers. The exposed fields were first and last name, billing address, credit card type, expiration date and the last four digits of the card, not the full card number. The bug was patched and OpenAI added checks so that requesting users do not get data belonging to other users [C18-M01-R2]. Lessons: - AI services inherit every classic risk: caching, concurrency, multi-tenancy and dependency bugs. - Conversation history is sensitive data and needs the same isolation as any user data. - Defence in depth at the application layer ("does this data belong to the requester?") catches failures in lower layers. - Regulators react: the Italian authority's action days later (Module 4) cited concerns including this breach.



## (FICTIONAL TEACHING SCENARIO): The demo that went to production ----------------------------------------------------------------------- This scenario is fictional. A team at Banyan Telecom built a support bot in a hackathon: all documents in one index, the refund API key in the prompt, and the model's answer rendered as HTML. It went live without review. An architecture review rebuilt it as the hardened BanyanBot configuration: per-customer retrieval, tools called by code with a policy check, secrets outside the prompt, output filtered and rendered as text, and a probe suite in CI.
