## SHAttered, 2017 - the first public SHA-1 collision -------------------------------------------------------------------------- Context: On 23 February 2017, researchers from CWI Amsterdam (Marc Stevens, Pierre Karpman) and Google (Elie Bursztein, Ange Albertini, Yarik Markov) announced the first practical SHA-1 collision. Two visibly different PDF files shared the SHA-1 value 38762cf7f55934b34d179ae6a4c80cadccbb7f0a, while their SHA-256 values differed. The computation took about nine quintillion SHA-1 computations, roughly 6,500 CPU-years and 110 GPU-years of parallel work [C15-M04-R2]. Browsers and certificate authorities had already been retiring SHA-1, and Git added collision detection. Lessons: - "Theoretical" weaknesses become practical. Plan migrations before the demonstration, not after. - Collision attacks threaten signatures and certificates, because an attacker can get one document signed and substitute another with the same hash. - Inventory hash use (certificates, signatures, integrity checks, deduplication), and keep algorithm identifiers in formats so you can move to SHA-256 or SHA-3 (agility).



## (FICTIONAL TEACHING SCENARIO): The fast hash table ------------------------------------------------------------------------- This scenario is fictional. A legacy Tamarind partner portal stored SHA-256(password) without salt. After a database backup leaked, many partner passwords were recovered quickly, and identical hashes revealed which partners shared passwords. The response was to force resets, migrate to Argon2id with per-user salts (wrapping the old hashes until next login), enable MFA, monitor for credential stuffing, and notify affected partners.
