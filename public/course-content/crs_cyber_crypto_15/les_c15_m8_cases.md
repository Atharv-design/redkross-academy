## Storm-0558, 2023 - key management at scale ------------------------------------------------------------------ Context: The US Cyber Safety Review Board's report on the 2023 Microsoft Exchange Online intrusion, released on 2 April 2024, found that the intrusion was preventable and resulted from a cascade of security failures. The actor used a Microsoft consumer (MSA) signing key from 2016 that remained valid in 2023 to forge authentication tokens. The report stated that Microsoft had not determined how the key was stolen. The intrusion affected 22 organisations and more than 500 individuals [C15-M08-R1] (see also Course 01 Module 6). Lessons for any cryptographic system: - Key lifecycle failures (old keys still valid, keys usable beyond their intended scope) can matter more than algorithm strength. - Verification logic must check that a key is valid for the specific purpose and audience. The capstone's header authentication and parameter bounds are small-scale versions of "validate everything before trusting it". - Key custody and rotation must be designed, monitored and audited, from a passphrase on a laptop to signing keys for a global identity platform.



## (FICTIONAL TEACHING SCENARIO): The tool without a version byte ------------------------------------------------------------------------ This scenario is fictional. A Tamarind team wrote an encryption script in 2019 with PBKDF2 at 10,000 iterations and no header. When they raised the parameters in 2024, older files could not be decrypted, because the tool could not tell which parameters a file used. They kept two versions of the tool, which caused confusion and errors. The rkcrypt design stores the KDF identifier and parameters in an authenticated header, so parameters can change without breaking old files.
