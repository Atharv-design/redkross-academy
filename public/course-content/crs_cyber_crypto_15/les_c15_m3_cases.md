## ROCA, 2017 - flawed RSA key generation in hardware -------------------------------------------------------------------------- Context: In October 2017, researchers from Masaryk University (CRoCS), with Enigma Bridge and Ca' Foscari University of Venice, disclosed CVE-2017-15361 (ROCA), presented at ACM CCS 2017. RSA keys generated by an Infineon software library used in smart cards and TPMs had a structure that let the private key be computed from the public key for practical key lengths, including 512, 1024 and 2048 bits. Infineon stated that the chip hardware itself was not affected; the flaw was in key generation. Estonia, where the chip was in more than 750,000 identity cards, suspended and re-certified affected cards. Other affected products included some TPMs, security keys and smart cards [C15-M03-R3]. Lessons: - Key generation is a single point of failure. A certified device can still produce weak keys. - Public keys can be tested. The researchers released detection tools, and organisations should be able to scan their key inventory. - Agility and replacement capacity matter. National ID and enterprise PKIs need plans to re-issue keys at scale. ## (FICTIONAL TEACHING SCENARIO): The unauthenticated exchange ------------------------------------------------------------------------- This scenario is fictional. A Tamarind IoT tracker agreed session keys with the server using X25519 but never verified the server's public key. In a lab test, an engineer placed a proxy that performed separate exchanges with the device and the server and relayed traffic undetected. The fix provisioned each device with the server's public-key fingerprint (pinning), and the server signed its ephemeral key, so only the genuine server could complete the handshake.
