## About this module

Symmetric cryptography needs a shared secret. Public-key (asymmetric) cryptography solves the problem of getting one. Each party has a key pair: a private key kept secret and a public key shared freely. Public keys let anyone encrypt to the owner or verify the owner's signatures, and key exchange lets two strangers derive a shared secret over a public network. This module covers RSA and elliptic-curve cryptography, key exchange with X25519 and HKDF, key sizes and security levels, key protection, and the transition to post-quantum algorithms.

## Why it matters

Every HTTPS connection, SSH login, signed software update and many national ID systems rely on public-key cryptography. When key generation goes wrong, the damage is wide. The 2017 ROCA flaw made RSA keys generated by a widely used smart-card library factorable from their public halves, affecting hundreds of thousands of national ID cards (case study).

## Where it is used

TLS and SSH, code signing, document signing (including India's digital signature certificates under the IT Act), secure messaging, hardware tokens and HSMs.

## Learning objectives

1. Explain key pairs and the separate uses of encryption, signatures and key agreement.
2. Use RSA-OAEP and explain its size limits and why padding matters.
3. Use elliptic-curve signatures (Ed25519, ECDSA) and key agreement (X25519).
4. Derive session keys with HKDF and bind them to context.
5. Choose key sizes by security level and protect private keys.
6. Plan for post-quantum migration.
