## Debian OpenSSL, 2008 - a predictable generator ---------------------------------------------------------------------- Context: Debian Security Advisory DSA-1571-1 (13 May 2008, CVE-2008-0166) announced that its OpenSSL package's random number generator was predictable, "caused by an incorrect Debian-specific change". Affected packages dated from version 0.9.8c-1, uploaded to Debian unstable on 17 September 2006, and the flaw reached the stable release. The advisory strongly recommended that all cryptographic key material generated on affected systems be recreated, including SSH, OpenVPN, DNSSEC and X.509 keys. All DSA keys ever used for signing or authentication on affected systems should be considered compromised. Keys generated with GnuPG or GnuTLS were not affected [C15-M01-R1]. Lessons: - Randomness code is safety-critical. A change that looks harmless can remove almost all entropy without any visible error. - Keys outlive the bug. Systems needed key regeneration and revocation, not just a package update. - DSA and ECDSA signatures also depend on randomness at signing time (Module 7), so a bad generator can expose keys that were generated correctly. - Downstream modifications of cryptographic code need expert review.



## (FICTIONAL TEACHING SCENARIO): The predictable reset link --------------------------------------------------------------------------- This scenario is fictional. Tamarind's legacy portal generated password reset tokens with random.seed(time.time()) and random.randint. A tester showed that tokens issued in the same second were identical, and that tokens could be regenerated from the issue time. The fix was secrets.token_urlsafe(32), single-use tokens with a 15-minute expiry, a SAST rule banning random in security code, and invalidating all outstanding tokens.
