Field modifiers change how a value matches: contains, startswith, endswith, all (every list value must match, rather than any), re (regular expression), and others such as base64offset, cidr and windash (the full list is in the modifiers appendix of the specification). A map in a selection is AND; a list of values is OR, unless the all modifier is used. Conditions combine selections with and, or, not and parentheses, and with the patterns "1 of `selection_*"` and "all of `selection_*"` [R1]. Two rules from the specification often catch people out:

- All values are case-insensitive strings, but regular expressions are case-sensitive by default.
- The backslash is an escape character before a wildcard (`*` or ?) or another backslash. A single backslash before an ordinary character is literal, so '\tar.exe' means backslash + tar.exe. Two backslashes mean one literal backslash, so to match the two backslashes that start a UNC path you must write four: ' \\\\'. The specification recommends four backslashes for consistency [R1].

Tamarind's first draft of the archive rule used ' \\', which matches a single backslash. sigma-cli's Splunk conversion exposed it (`CommandLine="*` `\\*"` rather than `"*` `\\\\*"`), and so did a new negative test (a rooted local path such as \Work must not match). The lab evaluator originally ignored Sigma escaping and was fixed to follow the specification.
