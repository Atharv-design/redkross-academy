## About this module

A security operations centre can only respond to what it can see, and it can only see what someone deliberately engineered it to see. Defensive engineering is the work behind that: deciding which threats matter most, which telemetry is needed to observe them, how that telemetry is collected, protected and kept, which detections turn it into alerts, and how the whole system is measured. This module treats the defensive stack as a product with requirements and a coverage score, using the fictional company Tamarind Freight as the running example.

## Why it matters

Most detection failures are not clever attacks; they are missing logs, workstations that never forwarded events, retention that expired before anyone looked, or rules that nobody tested. Coverage that is measured can be improved; coverage that is assumed cannot.

## Where it is used

Detection engineering teams, SOC platform teams, security architecture reviews, audit evidence for logging obligations (for example the 180-day log retention in the CERT-In Directions of 2022, covered in Course 01 Module 7), and board reporting on defensive capability.

## Learning objectives

1. Describe a layered defence architecture and the role of each layer in prevention, detection and response.
2. Build a threat-informed list of priority techniques from a threat model.
3. Design a telemetry strategy covering sources, fields, transport, retention, time and integrity.
4. Explain how ATT&CK 20.1 organises detection knowledge (detection strategies, analytics and data components).
5. Build and interpret a coverage matrix with honest scoring.
6. Prioritise engineering work from coverage gaps.
