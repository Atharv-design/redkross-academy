## CrowdStrike Channel File 291, July 2024 Context: on 19 July 2024 CrowdStrike delivered two new IPC Template Instances to Windows sensors as Rapid Response Content in Channel File 291 [C20-M04-R2]. The IPC Template Type defined 21 input parameter fields, but the integration code supplied only 20 values. Earlier instances used a wildcard for the 21st input, so the mismatch never surfaced. One of the new instances introduced a non-wildcard criterion for the 21st input. The Content Validator assessed it on the expectation of 21 inputs, and sensors hit an out-of-bounds read. Microsoft estimated that 8.5 million Windows devices were affected, less than one percent of all Windows machines [C20-M04-R3]. Mitigations in CrowdStrike's root cause analysis (6 August 2024) include runtime bounds checks, expanded Template Type testing, validation of Template Instances inside the Content Interpreter, staged deployment of Template Instances, and customer control over the delivery of Rapid Response Content [C20-M04-R2]. Lessons for detection engineering: content is code even when it is "just configuration". Tests must exercise the real interpreter with the real inputs, not a validator's model of it. Staged rollout and customer control limit blast radius. This course's rules only alert, but the same discipline applies to anything that ships to endpoints.



## (FICTIONAL TEACHING SCENARIO): The two-backslash bug This scenario is fictional, but it is based on a real mistake made while building this course's lab. Tamarind's UNC-path rule passed its tests for a month, because the only positive test happened to contain a UNC path and the matcher treated escaping loosely. A reviewer converting the rule to Splunk noticed a pattern with a single backslash. Adding the negative test "tar_rooted_local_path" showed that the rule also matched local paths that start with one backslash. Lessons: convert and read the output; write negative tests for near-misses; make the test tool follow the specification, not the author's intuition.
