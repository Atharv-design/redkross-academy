logsource names the kind of data (category: process_creation; product: windows; service: security) rather than a vendor index. The Sigma taxonomy appendix defines field names for each category. A converter (pySigma, used by sigma-cli) turns a rule into a backend query language such as Splunk SPL or Elastic ES|QL. Processing pipelines map Sigma log sources and field names to your platform's index names and fields. Without a pipeline, conversion assumes that your field names already match Sigma's. The lab uses "--without-pipeline" because its fields already follow Sigma names, and it uses a small evaluator (rk_sigma.py) so that you can read every line of the matching logic. Real deployments should use pySigma with the correct pipeline and test the converted query in the target platform.
