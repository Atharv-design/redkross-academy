## NIST CFTT - testing the tools examiners rely on ----------------------------------------------------------------------- Context: NIST's Computer Forensics Tool Testing (CFTT) project establishes a method for testing forensic software and hardware through specifications, test procedures, test criteria, test sets and test hardware. The categories include hardware and software write blocking, disk imaging, deleted-file recovery, file carving, Windows registry tools and SQLite. Supported by DHS, it partners with DHS Science and Technology to make tool testing reports available to the public [C09-M02-R1]. Lessons: - Write blockers and imagers are not trusted by default. They are tested against published specifications, version by version. - Laboratories should keep a record of which tool versions were validated and how. This supports repeatability and answers challenges in court. - Testing your own configuration with known data, as this module's lab does with a known hash, is the small-scale version of the same idea.



## (FICTIONAL TEACHING SCENARIO): The imaged evidence disk ------------------------------------------------------------------------------ This scenario is fictional. A rushed responder at Tamarind Logistics typed "of=/dev/sdb" instead of "of=/mnt/evidence/web01.dd" and overwrote the suspect disk with the contents of the analysis workstation's disk. The original evidence was destroyed. Lessons: identify devices by serial number and size before every command; use a hardware write blocker on the source; and use tools that refuse to write to the source device.
