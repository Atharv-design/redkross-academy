A write blocker lets an examiner read a storage device while preventing writes to it. Hardware write blockers sit between the device and the workstation and intercept write commands. Software write blockers configure the OS to refuse writes, for example through registry policy on Windows or by setting the block device read-only on Linux (blockdev --setro). They are cheaper but depend on correct configuration.

**Why it matters:** simply attaching a disk can trigger writes. Operating systems may update metadata, replay file-system journals or offer to "repair" volumes. On Linux, even a read-only mount of a journalled file system can replay the journal unless options such as noload (ext4) are used. Examiners should image the device rather than mount it, and analyse the image.

**Validation:** NIST's Computer Forensics Tool Testing (CFTT) programme develops test specifications and methods for hardware and software write block, disk imaging, deleted file recovery and other tool categories. DHS Science and Technology partners with CFTT to publish test reports [R1]. Check the reports for the tools and versions you use, and test your own setup with a known device before casework.
