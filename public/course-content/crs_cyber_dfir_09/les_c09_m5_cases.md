## BTK, 2005 - document metadata ----------------------------------------------------- Context: In February 2005 the "BTK" serial killer in Wichita, Kansas, who had taunted police for decades, sent a floppy disk to a local television station. Contemporaneous reporting describes investigators examining a Microsoft Word file on the disk, whose metadata pointed to Christ Lutheran Church and a user named "Dennis". Police linked this to Dennis Rader, the church council president. Rader was arrested on 25 February 2005, after DNA evidence also linked him to the crimes [C09-M05-R2]. Lessons: - Application metadata (author, organisation, last saved by) can identify the system or licence a document came from. It led investigators to a lead, which they then corroborated with independent evidence (DNA). - Metadata is a lead, not proof. It can be edited or inherited from templates. - Users often misjudge what files reveal about them. Verification note: from contemporaneous news reports via web search. Some popular accounts differ on details, such as whether the file was deleted, so this case study states only the consistently reported facts.



## (FICTIONAL TEACHING SCENARIO): The service at 02:13 -------------------------------------------------------------------------- This scenario is fictional. On a Tamarind file server, the examiner found System event 7045 at 02:13 UTC installing a service named "WinUpdSvc" from C:\ProgramData\u.exe. Five minutes earlier there was a 4624 type 3 logon by account svc_backup from 10.20.0.44, followed by 1102 at 02:40. Prefetch was disabled on the server, but Amcache recorded u.exe's SHA-1, which matched a known remote-access tool. Joining the logon ID across events tied the service installation to the svc_backup session. The examiner reported that account svc_backup, from 10.20.0.44, installed the service. They did not claim that the backup administrator did so.
