Active Directory depends on DNS completely. Clients find DCs not by a configured address but by querying DNS for service (SRV) records: a client looking for a DC asks for _ldap._tcp.<domain>, and a client looking for the Kerberos service asks for _kerberos._tcp.<domain>. If DNS is wrong, nothing works - domain join fails, logon fails, Group Policy fails. In the lab you will see this directly: the tool that manages Group Policy could not find a DC until the resolver pointed at the domain's own DNS, which serves those SRV records (deep dive). DCs replicate changes to each other on a schedule (and urgently for some changes such as account lockout). Replication uses update sequence numbers and version stamps to converge; conflicts are resolved deterministically.
