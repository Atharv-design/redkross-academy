NTLM is the older challenge-response protocol that predates Kerberos in the Windows world. It is weaker: it has no mutual authentication by default, it is vulnerable to relay and to pass-the-hash (the NT hash is password-equivalent, Module 5), and it gives the defender far less telemetry than Kerberos. Yet it persists because some scenarios fall back to it: access by IP address rather than host name (no SPN to request a ticket for), workgroup or cross-trust edge cases, and old applications. Defensive direction: measure where NTLM is still used (Windows can audit this), remove the causes, and then restrict or disable NTLM; add members to the Protected Users group, which blocks NTLM for them entirely [R3].
