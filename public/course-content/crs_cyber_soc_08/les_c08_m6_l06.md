Each detection should ship with: purpose and threat; logic explanation; data sources and required fields; ATT&CK mapping and version; severity and confidence rationale; known false positives; triage steps for analysts (what to check first); response guidance; test cases; owner and review date. Store rules in version control; require review for changes; run tests in a pipeline (detection as code). Review rules when data sources change (the parser update in Module 3), when ATT&CK changes, and when false-positive rates rise.
