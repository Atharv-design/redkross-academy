| Term | Meaning |
|---|---|
| Least privilege | minimum access for minimum time. |
| Defence in depth | independent layers; one failure is not fatal. |
| Secure by default | the default configuration is the safe one (Course 12 M06). |
| Fail safe / fail closed | on error, deny rather than allow (with availability trade-offs designed explicitly). |
| Economy of mechanism | simple designs are easier to verify. |
| Complete mediation | every access is checked, not only the first. |
| Separation of duties | no single role can complete a sensitive action alone (e.g., key administration vs data access). |
| Minimise attack surface | remove unused services, ports, accounts. |
| Assume breach | design to detect, contain and recover. |
| Open design | security does not depend on secrecy of design (Kerckhoffs, Course 15 M01). |

Principles conflict at times (fail closed vs availability); record the resolution as a decision (L06).
