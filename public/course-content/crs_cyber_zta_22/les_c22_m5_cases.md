## Storm-0558, 2023 - signing key custody and token validation ------------------------------------------------------------------------ Context: The US Cyber Safety Review Board's report on the summer 2023 Microsoft Exchange Online intrusion (announced 2 April 2024) found the intrusion preventable and the result of a cascade of security failures. The actor used a Microsoft consumer (MSA) signing key created in 2016 that was still valid in 2023 to forge tokens and access email of organisations and individuals - about 22 organisations and more than 500 individuals; the report stated that Microsoft had not determined how the key was stolen [C22-M05-R1] (see Courses 01, 15, 17). Architecture lessons: - Signing keys are tier-0 assets: generate and hold them in HSMs, rotate them, and retire old keys decisively. - Validation must enforce scope: a key for one issuer or audience must not be accepted for another. - Monitor key and token use; anomalies in token issuance are detection opportunities. - Customers need logs to detect provider-side failures (Module 6).



## (FICTIONAL TEACHING SCENARIO): The tenant ID in the URL --------------------------------------------------------------------------- This scenario is fictional. Tamarind's partner portal took the partner ID from the URL path to scope queries. A partner changed the ID and viewed another partner's shipments. The fix derived tenant ID from the authenticated token, added database row-level security keyed to the session's tenant, and introduced automated cross-tenant tests in CI. The architecture standard now forbids client-supplied tenant identifiers for authorisation.
