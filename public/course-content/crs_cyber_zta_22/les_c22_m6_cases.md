## CrowdStrike Channel File 291, July 2024 - the failure mode of a trusted component ------------------------------------------------------------------------ Context: CrowdStrike's preliminary post-incident review (24 July 2024) states that on Friday 19 July 2024 at 04:09 UTC it released a content configuration update for the Windows sensor, and that Windows hosts running sensor version 7.11 and above that were online between 04:09 and 05:27 UTC and received it were affected; the defect was reverted at 05:27 UTC, and Mac and Linux hosts were not impacted. Problematic content in Channel File 291 resulted in an out-of-bounds memory read and a Windows crash. The review says that "due to a bug in the Content Validator", one of two Template Instances passed validation despite problematic content [C22-M06-R1]. Microsoft estimated that the update affected 8.5 million Windows devices, less than one percent of all Windows machines [C22-M06-R2]. Commitments in the review: additional validation checks; a staggered deployment strategy "starting with a canary deployment"; and giving customers greater control over when and where Rapid Response Content is deployed [C22-M06-R1]. Architecture lessons: - Security agents are tier-0 components with privileged failure modes; include them in failure-mode analysis (L03). - Update channels that reach every host at once are single points of failure (L04); rings and organisation-controlled timing reduce blast radius. - Recovery at scale depends on out-of-band access, encryption recovery keys and documented procedures (L05). - Monitoring must show fleet health quickly: crash rates and agent heartbeats are resilience telemetry, not only security telemetry.



## (FICTIONAL TEACHING SCENARIO): The PDP that failed open ------------------------------------------------------------------------- This scenario is fictional. Tamarind's PDP cluster ran in one zone. During a zone outage the gateways, configured to fail open, admitted every request to the shipment admin portal for 40 minutes. Nothing malicious happened, but the post-incident review found no record of who accessed the portal in that window, because the gateway logs were buffered locally and lost. The remediation: PDPs in three zones, fail closed for restricted resources with a break-glass path, gateway logs buffered to disk and forwarded to two collectors, and an alert on the fail-safe path (signal M2).
