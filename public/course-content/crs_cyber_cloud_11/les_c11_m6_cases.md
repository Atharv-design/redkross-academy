## Microsoft Power Apps portals, 2021 - an insecure default ------------------------------------------------------------------------ Context: On 23 August 2021 UpGuard published research titled "By Design: How Default Permissions on Microsoft Power Apps Exposed Millions". It reported a total of 38 million records across portals and that it notified 47 entities of exposures involving personal information. The cause was a default: lists had table permissions disabled by default, and if those configurations were not set and the OData feed was enabled, anonymous users could access list data. Microsoft initially considered the behaviour to be by design; it then made table permissions enabled by default for newly created portals and pointed to the Portal Checker to detect lists allowing anonymous access [C11-M06-R1]. Configuration lessons: - Review the defaults of every SaaS and PaaS feature you adopt against your own policy; "by design" may not match your risk appetite. - New secure defaults often apply only to new resources; existing ones need a posture check. - Provider tools (Portal Checker) and CSPM rules turn a one-off fix into a continuous control.



## (FICTIONAL TEACHING SCENARIO): The exception that never expired ------------------------------------------------------------------------ This scenario is fictional. A Tamarind team suppressed "RDS publicly accessible" for a migration in 2024 with a comment "temporary". Two years later the database still accepted connections from the internet. The fix: suppressions now require an owner and expiry date in a central exceptions file, a CI check fails when an exception expires, and the posture report lists exceptions by age.
