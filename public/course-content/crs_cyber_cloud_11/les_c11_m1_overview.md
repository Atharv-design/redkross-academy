## About this module

Cloud computing changes who builds, runs and secures each part of a system. This module establishes the vocabulary and mental models used in the rest of the course: the NIST definition of cloud computing, service models (IaaS, PaaS, SaaS) and deployment models; how AWS and Azure organise resources into accounts, subscriptions, regions and availability zones; the shared responsibility model that divides security duties between provider and customer; and a defender's method for cloud threat modelling that maps assets and trust boundaries to preventive controls, log sources and owners.

## Why it matters

In August 2021 researchers at Wiz disclosed "ChaosDB": a flaw in a provider-managed notebook feature of Azure Cosmos DB, enabled by default for some accounts, that could expose customers' database primary keys. Microsoft disabled the feature within 48 hours and asked affected customers to rotate their keys (case study). The provider fixed its part; only customers could rotate their own keys - shared responsibility in action.

## Where it is used

Cloud adoption and landing-zone design, architecture reviews, vendor and SaaS risk assessment, audit scoping (which controls are inherited from the provider), and incident planning for provider-side events.

## Learning objectives

1. Apply the NIST definition: essential characteristics, service models and deployment models.
2. Describe the AWS and Azure resource hierarchies and global infrastructure.
3. Allocate security responsibilities between provider and customer for IaaS, PaaS and SaaS.
4. Identify the control plane and data plane and why identity is the main perimeter.
5. Build a cloud threat model that links assets and trust boundaries to controls, logs and owners.
6. Recognise provider-side risk and the customer actions it requires.
