**For a compromised instance:**

1. Do not terminate it - that destroys volatile and disk evidence.
2. Isolate: replace its security groups with a quarantine group that has no ingress or egress rules (existing tracked connections may need handling); detach it from load balancers and auto scaling.
3. Preserve: snapshot volumes (and copy to the forensic account); capture memory with an approved tool if the case requires it; export relevant logs; record instance metadata.
4. Tag resources with the case ID and status so nobody "cleans up" evidence.
5. Record hashes of exported evidence and maintain chain of custody (Course 09).

Execution-tested continuation of the lab:

```text
------------------------------------------------------------- BEGIN OUTPUT
== 4. quarantine instance

== 5. snapshot volumes and tag with case ID

  'quarantined')]
--------------------------------------------------------------- END OUTPUT
```

The same boto3 calls (update_access_key, put_user_policy, modify_instance_attribute, create_snapshot, create_tags) work against an account you own; in a real incident run them under the IR role with each action logged. IDs are generated by the mock and will differ.
