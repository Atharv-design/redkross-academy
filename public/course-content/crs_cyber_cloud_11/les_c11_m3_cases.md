## Capital One, 2019 - a misconfigured WAF and the credentials behind it ------------------------------------------------------------------------ Context: The US Department of Justice's case page for United States v. Paige Thompson describes the 2019 intrusion into Capital One's cloud environment as enabled by a misconfigured web application firewall; the defendant was convicted in June 2022 [C11-M03-R1]. The OCC assessed a USD 80 million civil money penalty against Capital One on 6 August 2020, citing failures in risk management for its move to the cloud [C11-M03-R3]. Public reporting put the number of affected people at more than 100 million. Network lessons (defensive): - Edge controls such as WAFs are configuration-heavy; their rules need review, testing and change control like code. - Workload credentials must be protected from request forgery: require IMDSv2 and keep instance roles least-privilege, so that one application flaw does not expose large data stores. - Data stores should be reachable only through expected network paths (endpoint-restricted bucket policies, Module 4). - Detect use of workload credentials from unexpected locations and unusual data access volumes (Module 5).



## (FICTIONAL TEACHING SCENARIO): The temporary rule ----------------------------------------------------------------------- This scenario is fictional. During an outage an engineer at Tamarind opened 3389 from 0.0.0.0/0 on an Azure NSG "for ten minutes". It stayed for four months until a posture scan flagged it. The response: rule removed, Azure Bastion deployed, an Azure Policy deny for inbound RDP/SSH from any source, and an alert on NSG rule changes. Break-glass network access is now a documented, time-limited procedure.
