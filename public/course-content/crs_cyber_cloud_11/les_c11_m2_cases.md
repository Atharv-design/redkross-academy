## Midnight Blizzard, 2023-24 - a test account without MFA ------------------------------------------------------------------------ Context: In guidance for responders published on 25 January 2024, Microsoft stated that it detected an attack by Midnight Blizzard on 12 January 2024. The actor used password spraying to compromise a legacy, non-production test tenant account that did not have MFA enabled, then compromised a legacy test OAuth application that had elevated access to the Microsoft corporate environment, and used it to grant access to mailboxes (including the full_access_as_app role). The actor used residential proxy infrastructure to make detection harder [C11-M02-R2]. Identity lessons: - Inventory every tenant and identity, including test and legacy ones; enforce MFA everywhere or remove the identity. - Treat application permissions and consents as privileged access with owners and reviews. - Detection must cover OAuth application changes and unusual application access to data, not only user sign-ins (Module 5). - Source-IP reputation alone is weak against residential proxies; use behaviour and identity signals.



## (FICTIONAL TEACHING SCENARIO): The deploy role that could become anything ----------------------------------------------------------------------- This scenario is fictional. Tamarind's CI role had iam:PassRole on `"*"` so pipelines could start instances "with whatever role they need". A review found that this let the pipeline attach the platform-admin role to an instance. The fix restricted PassRole to two application role ARNs with an iam:PassedToService condition for EC2, added a permission boundary to team-created roles, and an alert on PassRole of administrative roles.
