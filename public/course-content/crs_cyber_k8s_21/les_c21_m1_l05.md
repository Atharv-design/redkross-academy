Linux splits root's powers into capabilities (CAP_NET_ADMIN, CAP_SYS_ADMIN and about forty others). Docker starts containers with a reduced default set of 14 [R2]: AUDIT_WRITE, CHOWN, DAC_OVERRIDE, FOWNER, FSETID, KILL, MKNOD, NET_BIND_SERVICE, NET_RAW, SETFCAP, SETGID, SETPCAP, SETUID and SYS_CHROOT. The lab decoded the CapEff mask 00000000a80425fb from inside a default nginx:alpine container to exactly those 14. Several are rarely needed by applications: NET_RAW allows crafting raw packets; DAC_OVERRIDE bypasses file permission checks; SETUID and SETGID allow changing identity. The robust pattern is "--cap-drop ALL" and, only if a test proves it necessary, "--cap-add" for the single capability required.

A surprise from the lab: the common reason given for keeping NET_BIND_SERVICE ("to bind to port 80 as non-root") did not apply. A process running as UID 10001 with no capabilities bound port 80 without error, because inside the container's network namespace net.ipv4.ip_unprivileged_port_start was 0, while on the host network namespace it was 1024 (m01_p2_output.txt). Check such assumptions on your own platform rather than keeping capabilities "just in case".

seccomp filters system calls. Docker applies a default profile that blocks calls rarely needed by applications and frequently involved in kernel exploits; the lab showed "Seccomp: 2" (filter mode) in both containers. Kubernetes does not apply a seccomp profile to pods unless asked (seccompProfile type RuntimeDefault), which is why the Restricted Pod Security level requires it (Module 5).

no_new_privs (Docker: --security-opt no-new-privileges; Kubernetes: allowPrivilegeEscalation: false) prevents a process from gaining privileges through setuid binaries or file capabilities after it starts. The lab showed NoNewPrivs 0 by default and 1 when set.

Finally, "--privileged" removes nearly all of these protections: according to Docker's documentation it gives all capabilities and access to all host devices [R2]. The lab itself needed "--privileged --pid=host" to read the host's namespace identifiers - a vivid demonstration of how much those two flags expose.
