## The Alpine NULL root password, CVE-2019-5021 Context: the CVE record published on 8 May 2019 states that versions of the official Alpine Linux Docker images since v3.3 contained a NULL password for the root user, and that systems using affected images with Linux PAM or another mechanism that uses the shadow file may accept a NULL root password. It is scored CVSS 3.0 9.8 [C21-M02-R3]. What happened: a configuration defect in a base image - not in any application - propagated into every image built on the affected versions. Exploitation depended on what the derived image installed and how it authenticated, which is exactly the kind of context a scanner cannot know. Response: fixed base images were published; derived images had to be rebuilt and redeployed, which required knowing which images used the affected bases. Lessons: base images are part of your supply chain and need owners, rebuild procedures and inventory. An SBOM or base-image record per deployed image turns "which of our images are affected?" from a project into a query. Configuration defects matter as much as package CVEs.



## (FICTIONAL TEACHING SCENARIO): The key in layer 3 Context: a Kestrel Pay (fictional) developer added a payment-provider sandbox key to .env, built an image with "COPY . /srv" and, to "clean up", added "RUN rm /srv/.env" in a later instruction. The image was pushed to a public repository by mistake. What happened: an external researcher extracted the earlier layer and found the key; the layer still contained the file even though the final filesystem did not. The provider's key-rotation process was run. Response: the repository was made private and the image deleted; .dockerignore and BuildKit secret mounts became mandatory; the linter rule RK-D05 and a pre-push secret scan were added to CI; the registry gained a policy that new repositories are private by default. Lessons: layers are additive history. Deleting a file later does not remove it. Prevent secrets from entering the build context.
