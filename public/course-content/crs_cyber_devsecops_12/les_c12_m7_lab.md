## Practical 1: Sign, verify and reject

---------------------------------------------

**Objective:** Run the signing and provenance labs and make deployment depend on verification.

**Difficulty:** Advanced.

**Required tools:** Docker; Git bash or Linux shell; LAB_ASSETS/C12.

**Prerequisites:** Lessons L05-L06.

**Environment setup:** from LAB_ASSETS/C12: sh signing_lab.sh; then sh provenance_lab.sh.

**Explicit authorised scope:** lab artefacts and keys generated by the scripts.

**Step-by-step instructions:**

1. Run both scripts and confirm "Verified OK", the tamper failure and the MATCH/MISMATCH lines.
2. Write deploy_gate.sh that runs cosign verify-blob and the provenance check, and exits non-zero unless both pass.
3. Test it with the original and the tampered artefact.
4. Explain which SLSA Build level the lab provenance reaches and why.

**Expected observations:** deploy_gate.sh exits 0 for the original and non-zero for the tampered file. The level is L1-style, because the provenance is self-generated.

**Troubleshooting:** if generate-key-pair fails, delete old cosign.key and cosign.pub first (the script does this).

**Cleanup:** delete the sign folder when done.

**Learning outcome:** you can make releases verifiable.

## Practical 2: Review a workflow for least privilege

-----------------------------------------------------------

**Objective:** Find and fix permission and supply-chain weaknesses in a workflow.

**Difficulty:** Advanced.

**Required tools:** text editor; GitHub hardening guide [R1].

**Prerequisites:** Lessons L02-L04; Technical deep dive.

**Environment setup:** none.

**Explicit authorised scope:** documentation exercise.

**Step-by-step instructions:**

1. Given a workflow with: no permissions key; actions referenced by @main; AWS keys in repository secrets; a pull_request_target trigger that checks out the fork's code and runs tests with secrets; and an inline script echoing the pull-request title. List each weakness and its risk.
2. Rewrite it using the deep-dive pattern: default read-only permissions, SHA pins, OIDC role, pull_request trigger without secrets for forks, and the title passed via env.
3. Add CODEOWNERS for the workflow directory.

**Expected observations:** at least five fixes, each mapped to a lesson.

**Troubleshooting:** consult the current GitHub documentation, because features evolve.

**Cleanup:** none.

**Learning outcome:** you can harden pipeline definitions.
