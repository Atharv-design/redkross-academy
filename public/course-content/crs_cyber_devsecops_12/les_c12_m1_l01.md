A traditional SDLC moves through requirements, design, implementation, verification, release and maintenance. Agile and DevOps compress these stages into short iterations and continuous deployment, so security practices must:

- shift left: happen earlier (requirements, design, the developer's editor);
- be automated: scanners and tests run on every commit and pull request;
- be developer-friendly: findings arrive in the tools developers already use, with clear fixes and few false positives;
- extend right: production monitoring, vulnerability response and feedback into the next iteration.

DevSecOps is a culture as well as a toolchain. Developers own the security of their code, and the security team provides paved roads: secure defaults, reusable libraries, templates and pipelines. Its role is enabling as well as policing.
