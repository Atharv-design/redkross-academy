## Apple "goto fail", 2014 - a warning that was off by default ------------------------------------------------------------------------ Context: In February 2014 Apple fixed CVE-2014-1266 in iOS 7.0.6 and 6.1.6, and soon after in OS X 10.9.2. A duplicated "goto fail;" line in the SecureTransport TLS code made the jump unconditional, so a signature check on the server's key exchange was skipped and verification "will never fail". Adam Langley's analysis noted that neither GCC 4.8.2 nor Clang 3.3 flagged the dead code under -Wall, although Clang's -Wunreachable-code warning (not part of -Wall) would have caught it. He also noted that a test case could have caught it but would be difficult to write, because the check sits deep in the handshake [C12-M04-R2] [C12-M04-R3]. Lessons: - Cheap static checks catch real security bugs. Know which warnings your defaults exclude and enable them for security-critical code. - Pair static analysis with negative tests (Module 3), including ones needing special harnesses. - Code review alone missed a duplicated line, and tools help reviewers.



## (FICTIONAL TEACHING SCENARIO): Death by noise -------------------------------------------------------------------- This scenario is fictional. Tamarind enabled a large default SAST rule pack on every repository with blocking on. In the first week, developers filed 400 suppressions, many as bare "nosemgrep" comments. A real f-string SQL finding was suppressed along with the noise. The recovery was: - start with a small set of high-confidence rules, such as this module's three; - block only on ERROR severity in new code; - require rule IDs and reasons in suppressions; - review suppression trends.
