Static analysis includes compiler warnings and linters, which are often the cheapest checks available. Enable strict warning sets and treat warnings as errors in CI for security-relevant code. Some useful warnings are not in the default "all warnings" set, as the "goto fail" case study shows. Language-specific linters (for example Bandit for Python security patterns, ESLint security plugins, gosec) complement Semgrep. Human code review remains essential for logic, authorisation and design, so use a review checklist built from your threat model and your top SAST findings.
