## About this module

Threat modelling is a structured design review. It asks what we are building, what can go wrong, what we will do about it, and whether we did a good job. It happens before and during development, when changing the design is cheap. It needs no special tools, only a diagram, a method and the right people in the room. This module teaches how to model a system as a data-flow diagram, identify assets and trust boundaries, use STRIDE to generate threats, express misuse as abuse cases with testable mitigations, and prioritise the results.

## Why it matters

Many serious weaknesses, such as missing authorisation, implicit trust between components or unsafe dependency sources, are design decisions that no scanner reports. Threat modelling is the activity that finds them.

## Where it is used

Design reviews for new features and services, architecture boards, security champions programmes, and compliance with secure-development frameworks (NIST SSDF practice PW.1).

## Learning objectives

1. Run a threat-modelling session using the four key questions.
2. Draw data-flow diagrams with processes, stores, external entities, flows and trust boundaries.
3. Identify assets and the security properties each needs.
4. Generate threats systematically with STRIDE.
5. Write abuse cases with mitigations and acceptance tests.
6. Prioritise and track threats in a register.
