## Codecov Bash Uploader, 2021 - a modified CI tool ------------------------------------------------------------------------ Context: Codecov reported that from 31 January 2021, an attacker periodically altered its Bash Uploader script, adding a line that sent the output of "git remote -v" and "env" from customers' CI environments to a third-party server. The access came from an error in Codecov's Docker image creation process, which let the attacker extract a credential (a Google Cloud Storage key, per its FAQ) needed to modify the script. On 1 April 2021 a customer noticed that the SHA checksum of the downloaded uploader did not match the published value and reported it. Codecov then secured the script. Codecov advised affected customers to treat CI secrets as exposed, rotate them, and audit their use [C12-M07-R5]. Lessons: - Third-party tools downloaded at build time run with your secrets. Verify checksums or signatures before execution. That check is what exposed this incident. - Minimise secrets in CI environments (OIDC, scoped tokens), so a leak of "env" exposes little. - Vendors' own build processes (here, image creation) are part of their customers' supply chain.



## (FICTIONAL TEACHING SCENARIO): The self-hosted runner --------------------------------------------------------------------------- This scenario is fictional. Tamarind's public open-source helper library used a self-hosted runner on the office network for faster builds. Workflows for fork pull requests ran on it. A reviewer noticed that the runner kept files between jobs and could reach the internal package mirror with write access. The team moved public repositories to ephemeral hosted runners, restricted the self-hosted runners to private repositories, and removed the runner's write credential.
