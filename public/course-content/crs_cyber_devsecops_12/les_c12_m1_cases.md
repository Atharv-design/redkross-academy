## CrowdStrike Channel File 291, 2024 - validation and staged rollout --------------------------------------------------------------------------- Context: On 19 July 2024 a CrowdStrike Falcon content update (Channel File 291) caused Windows systems to crash. Microsoft estimated that about 8.5 million Windows devices were affected, less than one per cent of Windows machines [C12-M01-R4]. CrowdStrike's root cause analysis describes a mismatch between the 21 input fields defined by a template type and the 20 inputs provided by the sensor code. This led to an out-of-bounds memory read in kernel space, which a content validator and testing did not catch. Remediation included bounds checking, additional validation and testing, and staged deployment of such content to customers [C12-M01-R3]. This was not a cyberattack, but it is a software assurance failure. Lessons for a secure SDLC: - Content and configuration updates need the same validation, testing and gates as code. - Gates should include tests for malformed and unexpected inputs (the 20-versus-21 mismatch), not only expected ones. - Staged rollout (canaries, rings) limits blast radius when a gate misses something. - Root-cause analysis (SSDF RV.3) should change the lifecycle, not just fix one bug.



## (FICTIONAL TEACHING SCENARIO): The gate that never failed ------------------------------------------------------------------------- This scenario is fictional. Tamarind added a SAST step to its pipeline, and for six months it showed a green tick. An auditor then noticed that the tool printed dozens of findings but exited with status 0. The pipeline only checked the exit status, so nothing was ever blocked. The fix was to enable the tool's fail-on-findings option, add a pipeline test that commits a known-bad file to a test branch and expects failure, and review the findings that had accumulated.
