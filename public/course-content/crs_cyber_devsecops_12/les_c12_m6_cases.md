## Uber, 2016 - an access key on a code-sharing site ------------------------------------------------------------------------- Context: The US Federal Trade Commission's April 2018 expanded settlement with Uber describes a 2016 breach. Intruders accessed consumer data stored with a third-party cloud provider "by using an access key an Uber engineer had posted on a code-sharing website". The FTC lists more than 25 million names and email addresses, 22 million names and mobile phone numbers, and 600,000 names and driver's licence numbers of US riders and drivers. The FTC also states that Uber paid the intruders USD 100,000 through its bug bounty programme and did not disclose the breach to consumers or the Commission until November 2017 [C12-M06-R1]. Lessons: - A single long-lived credential in code gave access to large volumes of personal data. Workload identity and short-lived credentials remove this class of risk. - Secret scanning must cover every place code is shared, not only the main repository. - Response and disclosure obligations matter as much as the technical fix. In India, CERT-In reporting and DPDP obligations would apply to comparable incidents (Course 01 Module 7).



## (FICTIONAL TEACHING SCENARIO): The debug page -------------------------------------------------------------------- This scenario is fictional. A Tamarind staging service was promoted to production with DEBUG=true. An unhandled error displayed an interactive error page listing environment variables, including the database password held in an environment variable. A customer reported it. The response was to revoke and rotate the password, review database logs, add the startup check from this module to the deployment, and move secrets to file mounts resolved from the secrets manager.
