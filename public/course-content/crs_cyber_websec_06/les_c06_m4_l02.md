An Insecure Direct Object Reference (IDOR) - called Broken Object Level Authorization in API terms - occurs when the application exposes a reference to an object (an id in the URL, form or JSON) and acts on it WITHOUT checking that the current user is allowed to access that object. The classic form: /account?id=1001 returns order 1001; change it to 1002 and you get someone else's order, because the server looked it up by id but never checked ownership. IDOR is CWE-639 and maps to A01 Broken Access Control [R2]. It is dangerous because it is trivial (edit a number) and exposes data directly. In the lab, /account?id= returns any order with no ownership check; findings.py confirms that user asha can read ravi's order 1002.
