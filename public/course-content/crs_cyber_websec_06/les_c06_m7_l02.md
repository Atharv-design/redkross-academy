Serialization converts objects to a byte/text form for storage or transport; deserialization reconstructs them. Insecure deserialization (CWE-502) occurs when an application deserializes UNTRUSTED data with a mechanism that can instantiate arbitrary objects or run code during reconstruction - for example Python's pickle, Java's native serialization, or unsafe YAML loaders. An attacker who controls the serialized bytes can craft input that executes code or alters application state when deserialized, often leading to remote code execution. The defences: never deserialize untrusted data with a code-capable format; use data-only formats (JSON parsed to plain structures) for untrusted input; if objects must be exchanged, sign/verify the data and restrict the allowed types. In Python specifically: never unpickle untrusted data - use json. Insecure deserialization maps under OWASP A08:2025 Software or Data Integrity Failures [R3].
