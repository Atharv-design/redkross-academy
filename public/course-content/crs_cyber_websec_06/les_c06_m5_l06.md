Confirming injection safely needs only a benign marker, not a destructive payload. For SQLi, the tool sends user=admin'-- and checks whether a session is returned (auth bypass) - it does not drop tables or exfiltrate data. For reflected XSS, it sends a harmless marker like <script>rk1</script> and checks whether it comes back UNencoded in the response (if it does, the browser would parse it). For stored XSS, it stores a marker review and checks whether it is rendered unencoded. All three are minimal, safe proofs on an owned target: the point is to demonstrate that the input crosses into the code/markup channel, not to cause harm. findings.py performs exactly these checks; the deep dive shows the results and fixes.
