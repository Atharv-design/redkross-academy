Secure code review connects each finding to the code that caused it and the pattern that prevents it. It is more reliable than black-box testing for finding injection, access-control and configuration issues, because you can see the data flow from input to sink. A review looks for the course's patterns: input concatenated into SQL (parameterise), output rendered without encoding (encode), objects fetched by client id without ownership checks (authorise), state-changing endpoints without CSRF tokens, user input used as file paths or URLs, and unsafe deserialization. A static aid can point to suspect lines, but a human confirms each in context. The lab's codereview.py scans a source file for these patterns; run on the vulnerable app it flags many lines, and on the hardened app far fewer - and the remaining hits (for example the presence of a do_POST that the reviewer must confirm now verifies a CSRF token) illustrate that a static hit is a lead, not a verdict.
