An ENTRY POINT is any place the application takes input. For each endpoint, record: the method(s) it accepts; the parameters (name, location, type); whether it requires authentication; what it does (reads data, changes state, returns a file, makes an outbound request); and what sink the input reaches. Inputs are not only visible form fields - they include URL path segments, query parameters, headers (Host, Referer, User-Agent), cookies, and request bodies (form or JSON). A thorough map treats every one of these as attacker-controlled. In the lab, /search takes q (reaches a SQL query and the HTML output), /account takes id (reaches an object lookup), /download takes file (reaches the file system), and /fetch takes url (reaches an outbound request) - four different sinks, four different weakness classes.
