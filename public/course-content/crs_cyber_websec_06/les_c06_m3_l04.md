Secure sessions follow a small set of rules: generate the token with a cryptographically secure random generator (e.g. Python secrets.token_urlsafe) so it is unforgeable; store session state server-side keyed by that random id; set the cookie HttpOnly, Secure and SameSite=Strict or Lax; issue a NEW token at login (prevent fixation) and invalidate it at logout; set an idle and absolute timeout; and bind sensitive actions to a fresh check. The hardened lab app (app_fixed.py) does exactly this: secrets.token_urlsafe(24) for the session id, a server-side SESSIONS table, and Set-Cookie with HttpOnly and SameSite=Strict (Secure added when served over HTTPS). After hardening, findings.py reports the weak-session check as absent.
