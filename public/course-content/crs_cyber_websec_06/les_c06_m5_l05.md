The primary XSS defence is CONTEXTUAL OUTPUT ENCODING: when placing untrusted input into a page, encode it for the context so it is rendered as text, not parsed as markup. In HTML body context, encode <, >, &, " and ' (for example Python's html.escape); different contexts (HTML attribute, JavaScript, URL, CSS) need their own encoding, which is why using a framework's auto-escaping templating is safest. Supporting defences: a Content-Security-Policy (CSP) that restricts where scripts may load from and disallows inline script, which reduces the impact of any XSS that slips through; HttpOnly cookies so stolen script cannot read the session; and input validation. Encoding at OUTPUT (not just input) is key, because the same data may be rendered in several contexts. The hardened lab app encodes all user-influenced output with html.escape and sets a CSP; both XSS findings are absent after the fix [R4].
