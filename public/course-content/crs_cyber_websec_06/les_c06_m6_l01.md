CSRF (CWE-352) abuses the fact that browsers send a site's cookies on every request to that site, including requests triggered by OTHER sites. If a state-changing action (change email, transfer funds) can be performed by a simple request and relies only on the session cookie, an attacker can host a page that silently submits that request; when a logged-in victim visits it, their browser sends the request WITH their valid cookie, and the server performs the action as the victim. The victim is authenticated; the request is forged. CSRF matters for state-changing requests; it does not let the attacker read the response, but it can change data. In the lab, /account/update changes a user's email on a POST with no anti-CSRF token, relying only on the (also insecure) session cookie - findings.py confirms the state change is accepted without a token.
