APIs expose application functions directly as HTTP endpoints, usually with JSON. The OWASP API Security Top 10 catalogues the recurring risks, of which the most important are [R5]: Broken Object Level Authorization (the API form of IDOR - an object fetched by id with no ownership check); Broken Authentication; Broken Object Property Level Authorization (over-exposing or accepting too many fields - excessive data exposure and mass assignment); and unrestricted resource consumption (no rate limits). APIs make these prominent because every endpoint is directly callable and object ids are usually in the URL. The security principles are identical to the rest of the course - the server enforces everything - but the surface is wider and more exposed.
