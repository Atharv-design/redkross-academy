Every injection flaw is the same mistake: untrusted DATA is combined with CODE or markup in a way that lets the data change what the code does. When you build a SQL string by concatenating user input, the input can add SQL. When you put user input into HTML without encoding, the input can add script. The same pattern produces OS command injection, LDAP injection, NoSQL injection and server-side template injection. Because the cause is shared, so is the cure: KEEP DATA AS DATA - never let input cross from the data channel into the code channel. Parameterisation does this for queries (the query structure is fixed; input is bound as data), and output encoding does this for markup (input is rendered as text, not parsed as markup). Validation (allowlist what input may be) is a useful supporting control but is not a substitute for these.
