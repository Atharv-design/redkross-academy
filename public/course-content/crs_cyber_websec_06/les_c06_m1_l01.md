A web application has two halves separated by a network: a CLIENT (the browser) that the user controls, and a SERVER that the organisation controls. The browser sends HTTP requests; the server returns HTTP responses (HTML, JSON, files). The single most important security fact follows from who controls what: the server does not control the client. Anything that happens in the browser - form values, hidden fields, JavaScript validation, cookies, headers - can be changed by the user or by malicious code, because it runs on a machine the user (or attacker) controls. Therefore the client is UNTRUSTED. Every security decision - authentication, authorisation, validation - must be enforced on the SERVER. Client-side checks are for user experience, never for security. The boundary between the untrusted client and the trusted server is the trust boundary, and most web weaknesses are a failure to enforce something at that boundary [R1].
