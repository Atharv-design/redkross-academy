## Why Broken Access Control is number one Context: OWASP compiles its Top 10 from large datasets of real applications. Broken Access Control rose to the number one position in the 2021 edition and remains number one in the 2025 edition, because access-control weaknesses were found in a very high proportion of tested applications and because their impact - unauthorised data access and actions - is severe. The category spans IDOR (CWE-639), missing function-level control, privilege escalation, and related CWEs including CWE-918 (SSRF, mapped under A01 in 2025) [C06-M04-R1]. Why it matters for this module: access control is the most impactful web weakness class, and it is largely a design-and-review problem rather than a tooling one - scanners miss logic flaws, so consistent server-side checks and human review are the defence. Lessons: treat access control as a first-class design concern; enforce object and function checks server-side everywhere; review new endpoints specifically for missing checks; and do not expect scanners to find these flaws for you.



## (FICTIONAL TEACHING SCENARIO): The incrementing invoice Context: Sahyadri Reads (fictional) let customers view an invoice at /invoice?id=NNNN, looking it up by id without checking ownership - the same pattern as the lab's /account. What happened: a customer noticed their invoice id and, out of curiosity, decremented it. Each change showed another customer's invoice - names, addresses and order details - because the server never checked that the invoice belonged to the logged-in user. One curious user could enumerate the entire invoice table by counting. Response: the team added an ownership check on every invoice access (the invoice's customer must equal the session user, or the user must be an admin); switched visible references to values that are not trivially enumerable where appropriate; added access logging; and reviewed every other object-by-id endpoint for the same gap. Lessons: never return an object by client-supplied id without an ownership check; sequential ids plus no authorisation equals mass data exposure; audit all object-by-id endpoints together, because the pattern repeats.
