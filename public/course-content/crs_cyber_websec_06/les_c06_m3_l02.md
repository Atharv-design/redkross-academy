Passwords must never be stored in plain text or with fast/un-salted hashes. A breach of the user table should not reveal passwords. The correct approach is a slow, salted PASSWORD HASH designed for the purpose: bcrypt, scrypt, or Argon2 (the modern recommendation), with a per-user random salt and a work factor tuned to be slow for attackers [R2]. Fast hashes (MD5, SHA-1, plain SHA-256) are wrong for passwords because they allow billions of guesses per second. The lab stores sample passwords in plain text purely so the teaching target is simple; the hardened design note is explicit that real systems must hash with Argon2id (or bcrypt/scrypt) and never store or log plain passwords. Verifying a password means hashing the input with the stored salt and comparing - never decrypting, because a correct password hash is not reversible.
