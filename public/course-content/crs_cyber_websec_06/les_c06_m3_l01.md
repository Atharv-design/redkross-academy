Authentication flaws arise when the login process can be bypassed, guessed or abused. Common examples: permitting weak or default passwords; allowing unlimited login attempts (enabling credential stuffing and brute force); revealing whether a username exists through different responses (user enumeration); transmitting credentials over plain HTTP; and building login on a query vulnerable to SQL injection (Module 5) so authentication is bypassed entirely. Defences: enforce strong password policy and screen against breached-password lists; rate-limit and lock out after repeated failures; return identical responses for "unknown user" and "wrong password"; require HTTPS; and build login on parameterised queries and a vetted authentication library. The lab's vulnerable login is bypassable by SQL injection (user=admin'-- ), which this module notes and Module 5 proves.
