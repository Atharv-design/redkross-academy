Multi-factor authentication adds a second factor beyond the password: something you have (an authenticator app generating time-based codes - TOTP; a hardware security key using WebAuthn/FIDO2) or something you are (biometrics). MFA sharply reduces account takeover, but it has weaknesses when designed poorly: SMS codes can be intercepted or SIM-swapped; TOTP codes can be phished in real time (the user is tricked into entering a code on a fake site); "MFA fatigue" push prompts can be approved by a worn-down user; and backup/recovery codes can be weak. The strongest widely-available factor is a phishing-resistant hardware security key (WebAuthn/FIDO2), because it binds the authentication to the real site's origin and cannot be replayed to a fake one [R3]. Design MFA to resist phishing, rate-limit prompts, and protect the enrolment and recovery paths - which are where attackers pivot.
