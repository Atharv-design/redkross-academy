## Insecure deserialization as a path to code execution Context: insecure deserialization has repeatedly led to remote code execution in widely used platforms, because several popular serialization mechanisms (Java native serialization, Python pickle, some YAML loaders) can instantiate arbitrary objects or invoke methods during reconstruction. When such a mechanism is used on data an attacker can influence - a serialized session cookie, a cached object, a message on a queue - a crafted payload can run code on the server. The weakness is catalogued as CWE-502 and sits under OWASP A08:2025 Software or Data Integrity Failures [C06-M07-R3]. Why it matters for this module: the lesson is to treat serialized data from untrusted sources as hostile and never to use a code-capable deserializer on it. Use data-only formats (JSON parsed to plain structures); if objects must be exchanged, authenticate the data (signing) and restrict allowed types. Lessons: never deserialize untrusted data with a code-capable format; prefer JSON; sign and type-restrict if objects are unavoidable; keep libraries patched.



## (FICTIONAL TEACHING SCENARIO): The reusable coupon Context: Sahyadri Reads (fictional) issued single-use discount coupons, but the checkout applied a coupon whenever it was present in the request and only marked it "used" in a step that could be skipped by calling the final order endpoint directly. What happened: a user applied one coupon repeatedly across many orders, and others skipped the payment step entirely by calling the order-completion endpoint out of sequence. Nothing was malformed; the WORKFLOW was abusable. Input validation and scanners saw only valid requests. Response: the team enforced the business rules server-side: a coupon is atomically marked used when applied and rejected thereafter; order completion verifies that payment succeeded and that each prior step occurred, in order; quantities and prices are validated and looked up server-side; and limits and idempotency keys prevent replay. Lessons: business logic flaws evade input validation; enforce every rule and state transition on the server; make single-use truly single-use; verify sequence; and never trust client-supplied business values.
