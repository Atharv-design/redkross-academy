Each flaw is confirmed with a minimal, safe proof on the owned target. CSRF: log in, then POST a state change WITHOUT a CSRF token and check it is accepted (a change to your own lab account - nothing external). SSRF: the tool stands up a throwaway loopback listener, asks the server to fetch that loopback URL, and confirms the SERVER connected to the caller-chosen location - proving the server will fetch an arbitrary URL, with all traffic on 127.0.0.1. Path traversal: request /download?file=../app.py and confirm a file outside the intended directory is returned. None of these touches any third-party system; all are read-only or self-contained on loopback. The deep dive shows the results and fixes.
