## About this module

This final module brings the course together into one authorised workflow: run the OWASP-aligned testing process on the lab application you own, review the code for the patterns behind each finding, produce a risk-ranked security report with remediation, apply the fixes, and RETEST to prove closure. You will use the lab's tools end to end - map, findings, cvss, report, retest and codereview - and complete a capstone that mirrors a real application security engagement from authorisation to verified fixes. The emphasis is on evidence and closure: a finding is only closed when a retest proves it.

## Why it matters

Finding weaknesses has little value unless they are reported clearly, fixed, and confirmed fixed. The security report is the deliverable that turns testing into risk reduction; secure code review connects each finding to the code that caused it and the pattern that prevents it; and retesting is what distinguishes "we think it is fixed" from "it is fixed". This module teaches the professional close-out that makes the whole exercise worthwhile - and it is the skill employers and clients actually pay for.

## Where it is used

Every application security assessment and penetration test close-out; secure development lifecycle gates; code review; vulnerability management; and the remediation-and-retest cycle that follows any finding.

## Learning objectives

1. Run the OWASP-aligned web testing workflow on an owned application.
2. Perform a secure code review connecting findings to code patterns.
3. Produce a risk-ranked security report with remediation.
4. Apply fixes and retest to confirm closure.
5. Score and prioritise findings with CVSS and context.
6. Complete an authorised capstone assessment with evidence.

## Before you start

**Prerequisites:** Modules 1-7.

**Estimated study time:** About 10 hours (plus the 16-hour capstone).
