Modern applications are often a thin browser front-end talking to an API (Application Programming Interface) - usually HTTP endpoints returning JSON. The security principles are identical (the client is still untrusted; the server still enforces everything), but APIs widen and expose the attack surface: every endpoint is directly callable, object identifiers are often in the URL (making IDOR, Module 4, common), and documentation or predictable patterns reveal endpoints. APIs also shift some risks - mass assignment, excessive data exposure, missing object-level authorisation - that the OWASP API Security guidance catalogues [R3]. For this course, the key point is that an API is just HTTP with structured data: everything you learn about requests, responses, sessions, authorisation and injection applies directly.
