ZERO TRUST (NIST SP 800-207) rejects the idea of a trusted internal network: no flow is trusted because of where it originates; every access must be explicitly authorised [R1]. Applied to segmentation, this means the default is DENY, and only explicitly listed flows are permitted - "assume breach" and ensure a compromised host has no default path anywhere. MICRO-SEGMENTATION pushes the boundaries down to individual workloads or small groups (not just large zones), so even within a tier, only required flows are allowed. The practical artefact is an ALLOWED-FLOW policy: a matrix of which (source, destination, port) flows are permitted; everything else is denied. The lab's rk_segmentation.json is exactly this - a zero-trust allowed-flow matrix for the six zones.
