## About this module

Prevention and detection must be fed by MONITORING - the collection and analysis of network telemetry - and backed by RESPONSE that can contain an incident. This module covers packet and flow analysis, network telemetry sources, and incident containment at the network layer. You will analyse the lab's flow telemetry with an offline tool, detecting a port scan, a beaconing host and segmentation violations, and reason about how to contain each. This is the defender's daily work: watch the network, spot the anomaly, and cut off the threat.

## Why it matters

You cannot respond to what you cannot see. Network monitoring shortens the time an attacker operates undetected and provides the evidence to understand and contain an incident. Flow data (who talked to whom, when, how much) is a scalable, privacy-preserving telemetry that reveals scans, beaconing, exfiltration and lateral movement; packet capture gives deep detail when needed. And when something is found, network-layer containment - isolating a host, blocking a flow, cutting a segment - can stop the spread while the response proceeds. Monitoring and response turn the architecture, firewalls, IDS and segmentation into a living defence.

## Where it is used

Network security monitoring; NetFlow/IPFIX and packet-capture analysis; the SOC (Course 08) and threat hunting (Course 20); and incident response, where network containment is a primary early action. This module connects network security to security operations.

## Learning objectives

1. Distinguish packet capture from flow telemetry and their uses.
2. Explain network telemetry sources and fields.
3. Detect scans, beaconing and policy violations in flow data.
4. Explain network-layer incident containment.
5. Analyse the lab telemetry and propose containment.
6. Connect monitoring to the SOC and incident response.

## Before you start

**Prerequisites:** Modules 1-4 (zones, firewall, IDS concepts, segmentation).

**Estimated study time:** About 9 hours.
