A STATEFUL firewall tracks the state of connections: when an internal host opens a connection outbound, the firewall remembers it and automatically allows the return traffic for that connection, without a separate inbound rule. A STATELESS filter, by contrast, examines each packet in isolation and needs explicit rules for both directions, which is error-prone. Stateful inspection (the norm since the 1990s) makes policies simpler and safer: you allow the initiating direction and the firewall handles the replies, and it can drop packets that do not belong to a known connection [R1]. Understanding state is important for reasoning about what a rule actually permits - an "allow app->db:5432" rule, on a stateful firewall, also permits the database's replies back to the app, without a separate rule.
