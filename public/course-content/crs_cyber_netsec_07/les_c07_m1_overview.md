## About this module

Network security starts with architecture: how you divide a network into trust zones, where you place boundaries and controls, and how you layer defences so that no single failure is catastrophic. This module covers threat modelling for networks, trust zones and boundaries, and the principle of defence in depth. You will model the fictional Himalaya Retail network into zones (internet, DMZ, application, database, user, management), reason about the threats to each boundary, and see how layered controls - firewalls, segmentation, monitoring - combine. The architecture you set here is the frame for every later module.

## Why it matters

Most damaging network incidents are failures of architecture, not of a single device: a flat network where one compromised laptop reaches the database; a management interface exposed to users; a DMZ that can initiate connections back into the core. Good architecture contains compromise, limits blast radius, and gives monitoring somewhere to watch. It is also the cheapest security to get right, because it is designed in rather than bolted on. Getting the zones and boundaries right is the highest-leverage decision in network security.

## Where it is used

Network and security architecture; cloud and data-centre design; threat modelling; audits and compliance (segmentation requirements); and the reference design every firewall, IDS and monitoring deployment is built against.

## Learning objectives

1. Perform a basic network threat model (assets, boundaries, threats).
2. Define trust zones and trust boundaries.
3. Explain and apply defence in depth.
4. Explain least privilege and default-deny at the network layer.
5. Model the lab network into zones and boundaries.
6. Relate architecture to the controls in later modules.
