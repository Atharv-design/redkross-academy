A firewall POLICY is an ordered list of RULES. Each rule matches on fields - source, destination, protocol, destination port - and has an action: ALLOW or DENY. Most firewalls use FIRST-MATCH semantics: the rules are evaluated top to bottom and the first rule that matches decides the flow; later rules are not consulted. Order therefore matters enormously - a broad early rule can override narrower later ones. A well-formed policy lists specific allow rules for required flows and ends with an explicit DENY ALL, so anything not matched is denied. The lab's firewall.py implements first-match evaluation: given a flow (source zone, destination zone, protocol, port) it reports which rule decides it, which makes the effect of ordering visible.
