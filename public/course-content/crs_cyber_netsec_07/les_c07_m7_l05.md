The lab's flowcheck.py turns 186 flow records into a short list of signals to triage. It computes TOP TALKERS (busiest sources - useful context), detects the PORT SCAN (one source hitting many ports fast), the BEACONING host (regular-interval contacts to the internet), and SEGMENTATION VIOLATIONS (flows the zero-trust matrix forbids). It aggregates the scan's many ports into a single signal rather than flooding the output - a small example of making alerts actionable (Module 3's tuning). The analyst reads the five signals, correlates them (the scanning source and the beaconing destination are both external host 203.0.113.50 - worth investigating together), and decides containment. This is network security monitoring in miniature.
