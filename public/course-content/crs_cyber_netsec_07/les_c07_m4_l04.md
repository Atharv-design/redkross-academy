A segmentation design on paper is worthless if the network does not enforce it. ACCESS POLICY VALIDATION checks that the ACTUAL flows (from configuration review or observed telemetry) match the intended allowed-flow policy, and flags any connection that violates it. This catches the gaps that creep in: a firewall rule that was supposed to block user->db but does not; a new application path that bypasses a boundary; a misconfigured ACL. Validation can be done against configuration (does the firewall policy implement the matrix?) and against telemetry (are there observed flows that the matrix forbids?). The lab's segmentation.py validates a list of observed/intended connections against the matrix and reports violations - the exact flows that cross a boundary the policy denies.
