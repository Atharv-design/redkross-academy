Reviewing an API configuration makes the controls concrete. The lab's apicheck.py reads a backend configuration and checks the mobile-API essentials: authentication required and strong (token validation, expiry), transport secured (TLS enforced, no cleartext), and backend hardened (authorisation enforced, rate limiting, safe errors, no excessive data). It reports each missing control as a finding with a severity and a PASS/FAIL verdict. An insecure configuration fails on multiple HIGH findings; a hardened configuration, with each control in place, passes - the same enforcing before/after evidence as the Wi-Fi and Bluetooth reviews (Modules 2 and 4). The deep dive runs both configurations. The point: API security is a set of server-side controls you can specify, check and enforce.
