A Bluetooth configuration review reads a device's pairing and security settings and flags weaknesses against NIST SP 800-121 Rev.2 guidance, each with a severity: association model (authenticated vs Just Works), LE Secure Connections (vs legacy), discoverability (on-demand vs always), default PIN, minimum encryption key size, and bonded-device review. The output is a prioritised findings list and a PASS/FAIL, re-runnable after hardening. As with Wi-Fi, this is an offline review - no Bluetooth radio activity - that produces evidence. The lab's btreview.py implements it, and the deep dive shows a weak device failing (Just Works, legacy pairing, always discoverable, default PIN, small key size) and a hardened one passing (Numeric Comparison, LE Secure Connections, on-demand discovery, no fixed PIN, 16-byte keys).
