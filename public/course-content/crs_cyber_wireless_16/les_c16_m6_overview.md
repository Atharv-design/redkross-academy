## About this module

Mobile app testing finds the weaknesses where an app fails to respect the platform model (Module 5). This module covers static inspection (reviewing the app's manifest, configuration and code without running it), dynamic testing (observing the app's behaviour), and the recurring theme of insecure data handling. You will run the lab's static reviewer over the demo app, finding and categorising its weaknesses against the OWASP MASVS, and learn how dynamic testing complements it.

## Why it matters

A mobile app handles sensitive data on a device the organisation does not fully control, and it talks to a backend over hostile networks. Testing finds the flaws - hardcoded secrets, cleartext traffic, data in shared storage, weak crypto, exposed components - before attackers do. Static inspection catches a large share cheaply and safely by reading the app; dynamic testing confirms runtime behaviour (what the app actually sends and stores). Insecure data handling, in particular, is so common that it anchors mobile testing. Being able to test an app systematically against the MASVS is the core mobile-security skill.

## Where it is used

Mobile application security testing (the MASTG methodology); secure mobile development (shifting testing left); app store and enterprise app vetting; and the assessment of any app before release. It is the mobile analogue of web app testing (Course 06).

## Learning objectives

1. Explain static inspection of a mobile app and what it reveals.
2. Explain dynamic testing and what it adds.
3. Explain insecure data handling and its forms.
4. Review the demo app statically and categorise findings by MASVS.
5. Explain how findings are prioritised and remediated.
6. Explain safe, authorised mobile testing.

## Before you start
