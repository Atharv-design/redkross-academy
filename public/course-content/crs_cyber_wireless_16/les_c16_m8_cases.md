## Defence-in-depth across the wireless-and-mobile surface Context: real organisations secure the wireless-and-mobile surface in layers, because no single control covers it: harden Wi-Fi and detect rogue APs at the radio edge, secure Bluetooth on devices, review mobile apps for insecure data handling, and harden the mobile API as the real boundary. Established guidance - NIST SP 800-153 (WLAN), SP 800-121 (Bluetooth), OWASP MASVS/MASTG (mobile apps) and the OWASP API Security Top 10 (APIs) - maps to exactly these layers [C16-M08-R1] [C16-M08-R2][C16-M08-R3]. Why it matters for this module: the capstone assessment covers all these layers because an attacker needs only one weak layer; defence-in-depth and an assessment that spans the surface are the response. Lessons: secure the whole surface in layers; assess across all of them; use the standard for each layer.



## (FICTIONAL TEACHING SCENARIO): The full assessment Context: HimalayaCorp (fictional) commissions a wireless-and-mobile assessment of its own network, Bluetooth fleet, mobile app and backend, authorised and scoped. What happened: the consolidated review (review.py, offline) enforced the Wi-Fi, Bluetooth and API controls from FAIL to PASS (3/3), and reported 16 mobile-app findings (9 HIGH, mostly insecure data handling) and 2 evil-twin APs. The team presented the result as scope, method, findings by area, enforcing evidence and remediation mapped to a secure baseline. Response: they hardened the three configurations (verified by the passing reviews), remediated the app per MASVS, and investigated and removed the rogue APs - then adopted the passing reviews as acceptance tests for an ongoing baseline. Lessons: a complete assessment spans wireless, Bluetooth, app and API; enforcing evidence proves the controls; the baseline makes the fixes durable - all within an authorised, offline, do-no-harm scope.
