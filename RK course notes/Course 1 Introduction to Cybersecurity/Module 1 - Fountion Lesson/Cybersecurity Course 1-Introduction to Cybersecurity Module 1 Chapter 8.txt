Part 4 — Concept from Scratch

Here is the central sentence of this lesson.

A cybersecurity professional is only as good as the toolkit they carry, and a toolkit is only as good as the person who maintains it.

Let me say that again, because it is the lesson of this entire lesson.

A cybersecurity professional is only as good as the toolkit they carry, and a toolkit is only as good as the person who maintains it.

Beginners think the toolkit is a list of software to install. They are half right. The toolkit is the software, yes, but it is also the configuration, the documentation, the update schedule, and the backup plan. A toolkit that is installed and then ignored is worse than no toolkit at all, because it gives you false confidence. You think you are prepared, and then when the incident hits, your tools do not work because they are out of date or misconfigured.

This lesson has two parts. First, we install the tools. Second, we build the maintenance plan. The maintenance plan is the part most courses skip, and it is the part that separates a hobbyist from a professional.

Part 5 — How It Works: The Toolkit, Layer by Layer
Layer 1: Choose Your Operating System

The first decision is what operating system your computer runs. This matters more than most beginners realise.

Windows. The most common operating system in the world. It is good for beginners, because almost every software tool supports it. It is also the most attacked operating system, because it is the most common. Most cybersecurity tools have Windows versions. If your computer runs Windows, you are fine.

macOS. The operating system that runs on Apple computers. It is based on Linux, which makes it powerful for technical work. It is less common than Windows, and some cybersecurity tools are Windows-only. If you have a Mac, you are fine, but you may need to install additional software for some tools.

Linux. The operating system that runs the internet. It is the most powerful option for cybersecurity work, because most security tools were written for it, and it gives you the most control. It is also the most difficult for beginners. If you are comfortable with the terminal, consider installing a Linux distribution like Ubuntu on your computer. If you are not, do not worry — you can install Linux tools on Windows using the Windows Subsystem for Linux (WSL), which gives you a Linux environment inside Windows.

My recommendation: Use whatever your computer already runs. Do not buy a new computer for this course. If you have Windows, enable WSL and use it for the technical work. If you have a Mac, use it directly. If you have Linux, you are already set up.

Layer 2: The Terminal

The terminal is the most important tool in cybersecurity, and it is the tool beginners are most afraid of. Let me say something that will make you feel better.

The terminal is just another way to talk to your computer. When you click a button in a graphical interface, the computer is running commands behind the scenes. The terminal lets you type those commands directly. It is not magic. It is not difficult. It is just text.

How to open the terminal:

On Windows: press the Windows key, type “terminal,” and press Enter. Or open “Command Prompt.”
On Mac: open “Applications,” then “Utilities,” then “Terminal.”
On Linux: open your terminal application. It is usually called “Terminal.”

Four commands you must know:

ls — list the files in the current folder. This is the most used command in the terminal.
cd — change folder. cd ~/cybersec-lab moves you into your lab folder.
mkdir — create a new folder. mkdir new-folder creates a folder called new-folder.
clear — clear the screen. This is just for neatness, but it helps.

The most important skill: copy and paste. You will be copying commands from lessons like this one into your terminal. Learn how to copy and paste in your terminal. On most systems, you can right-click to paste, or use Ctrl+V. If it does not work, look up how to paste in your specific terminal.

Layer 3: Python

Python is the most important programming language in cybersecurity. It is used for automation, log analysis, penetration testing, malware analysis, and data processing. Almost every security tool you will use has a Python component, and you will write your own Python scripts to solve problems.

How to install Python:

On Windows: go to python.org, download the latest Python 3 installer (the 64-bit version), and run it. During installation, make sure the box that says “Add Python to PATH” is checked. This is the most common mistake — if you do not check this box, the terminal will not find Python.
On Mac: Python usually comes pre-installed. Open Terminal and type python3 --version to check. If it says something like “Python 3.11,” you are set up.
On Linux: Python is usually pre-installed too. Type python3 --version to check. If it is not installed, open your package manager and install it. On Ubuntu, the command is sudo apt install python3.

How to test it:
Open your terminal and type:

python3 --version

You should see something like Python 3.11.6. If you see an error saying “command not found,” go back and check your installation.

Now type:

python3 -c "print('Hello from Python')"

You should see Hello from Python. If you do, Python is working.

Layer 4: The Code Editor

You need a place to write code. The default text editors — Notepad on Windows, TextEdit on Mac — are not good enough, because they do not help you find mistakes.

Install VS Code. It is free, it is excellent, and it is the most popular code editor in the world. It runs on Windows, Mac, and Linux. It has features that make coding easier: syntax highlighting (colouring code so you can read it), error detection (underlining mistakes in red), and extensions (add-ons that add new features).

How to install VS Code:
Go to code.visualstudio.com, download the version for your operating system, and run the installer. The default settings are fine. Once it is installed, open it, and you are ready to write code.

Layer 5: The Core Security Tools

Now the actual security tools. These are the ones you will use in every future lesson.

Tool 1: nmap — the network scanner.
Nmap is the most important tool in cybersecurity. It scans networks to find what devices are there, what services they are running, and what version of the software they are running. It is used by attackers to find targets, and by defenders to find their own vulnerabilities. It is legal, it is free, and you will use it in almost every lesson from here on.

How to install nmap:

On Windows: download the installer from nmap.org and run it. The default settings are fine.
On Mac: open Terminal and run brew install nmap. If you do not have Homebrew, install it from brew.sh.
On Linux: open your package manager and install nmap. On Ubuntu: sudo apt install nmap.

How to test nmap:
Open your terminal and type:

nmap --version

You should see a version number like Nmap 7.92. If you do, nmap is installed.

Now run your first scan. This scans your own computer to see what services are running:

nmap localhost

You will see a list of “ports” and the services running on them. This is what a scan looks like. You will learn to read it in a later lesson.

Tool 2: Wireshark — the network analyser.
Wireshark captures and displays the packets of data travelling across a network. It shows you exactly what is being sent between computers. It is the most powerful network analysis tool in the world, and it is free.

How to install Wireshark:

On Windows: download the installer from wireshark.org and run it.
On Mac: run brew install wireshark.
On Linux: run sudo apt install wireshark on Ubuntu.

How to test Wireshark:
Open Wireshark from your applications. You will see a list of network interfaces. Click “Start” on your main network connection, and you will see packets flowing in real time. Do not worry about understanding them yet. Just know that the tool works.

Tool 3: tshark — the command-line version of Wireshark.
This is the same tool as Wireshark, but you run it from the terminal. It is faster, it can be scripted, and it is what professionals use when they need to automate network analysis.

How to test tshark:
Open your terminal and type:

tshark --version

You should see a version number. If you do, tshark is installed.

Tool 4: VS Code — your code editor.
Already installed in Layer 4. We will use it for Python scripts.

Tool 5: Git — version control.
Git is a tool that tracks changes to your code. It lets you save versions, go back to earlier versions if you make a mistake, and share your code with others. It is essential for professionals, and it is free.

How to install Git:

On Windows: download the installer from git-scm.com and run it. The default settings are fine.
On Mac: run brew install git or install Xcode Command Line Tools.
On Linux: run sudo apt install git on Ubuntu.

How to test Git:
Open your terminal and type:

git --version

You should see git version 2.38 or similar.

Part 6 — Example: Your First Network Scan

Let us now use nmap to do something real. This is your first hands-on skill.

Step 1: Open your terminal.

Step 2: Run a basic scan on your own computer.
Type:

nmap localhost

You will see output that looks something like this:

Starting Nmap 7.92 ( https://nmap.org ) at 2026-11-06 10:00 IST
Nmap scan report for localhost (127.0.0.1)
Host is up (0.00010s latency).
Not shown: 995 filtered ports
PORT    STATE SERVICE
22/tcp  open  ssh
80/tcp  open  http
443/tcp open  https

Step 3: Read the output.

PORT — the port number and whether it uses TCP or UDP.
STATE — open means a service is running and accepting connections. closed means the port is reachable but no service is running. filtered means nmap could not determine the state, usually because a firewall is blocking the probe.
SERVICE — the name of the service running on that port.

Step 4: Run a version scan.
This tells you the version of the software running on each port:

nmap -sV localhost

This takes longer, but it gives you much more information. You will see something like OpenSSH 8.9p1 Ubuntu on port 22, which tells you exactly which version of SSH is running.

Step 5: Write it down.
Add this to your toolkit log:

2026-11-06: First nmap scan completed.
Tool: nmap
Command: nmap localhost
Result: [copy the output]

Part 7 — Your First Python Script

Now let us write a simple Python script. This is your first piece of original code, and it is going to be a network port checker — a tool that checks whether a list of ports is open on a target computer. It is simple, it is useful, and it teaches you the core skill of writing code to solve security problems.

Step 1: Open VS Code.

Step 2: Create a new file.
Go to File → New File, and save it as ~/cybersec-lab/scripts/port-checker.py.

Step 3: Type this code.

python
#!/usr/bin/env python3
"""
Simple Port Checker
Checks whether common ports are open on a target host.
Usage: python3 port-checker.py <target>
"""

import socket
import sys

# Common ports and the services that usually run on them
COMMON_PORTS = {
    22: "SSH",
    80: "HTTP",
    443: "HTTPS",
    3306: "MySQL",
    3389: "RDP",
    8080: "HTTP-Alt",
}

def check_port(host, port, timeout=2):
    """Try to connect to a port. Returns True if open, False if closed."""
    try:
        sock = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
        sock.settimeout(timeout)
        result = sock.connect_ex((host, port))
        sock.close()
        return result == 0
    except Exception as e:
        print(f"Error checking port {port}: {e}")
        return False

def main():
    if len(sys.argv) < 2:
        print("Usage: python3 port-checker.py <target>")
        print("Example: python3 port-checker.py localhost")
        sys.exit(1)

    target = sys.argv[1]
    print(f"Scanning {target} for common ports...")
    print("-" * 40)

    for port, service in COMMON_PORTS.items():
        if check_port(target, port):
            print(f"  [OPEN]  Port {port:5d}  {service}")
        else:
            print(f"  [CLOSED] Port {port:5d}  {service}")

    print("-" * 40)
    print("Scan complete.")

if __name__ == "__main__":
    main()

Step 4: Run it.
Open your terminal, navigate to your scripts folder, and run:

python3 ~/cybersec-lab/scripts/port-checker.py localhost

You will see a list of ports and whether they are open or closed. This is your first working security tool.

Step 5: Save it.
This script is yours. It is original code that you wrote. Keep it, improve it, and add to it over the course. In six months you will look back at it and be surprised at how far you have come.

Part 8 — The Maintenance Plan: The Part That Separates Professionals from Hobbyists

Here is the part that most courses skip, and it is the most important part of this lesson.

A toolkit that is not maintained is a liability, not an asset. An outdated tool will fail when you need it most. A misconfigured tool will give you false information. A tool that nobody documented will be forgotten in six months.

The maintenance plan has four parts:

Part 1: Weekly updates.
Every tool you install needs security updates. Set a reminder to check for updates once a week. On Windows, use Windows Update. On Mac, use Software Update. On Linux, use your package manager. For tools that are not part of the operating system, check their websites or use their built-in update features.

Part 2: Monthly backups.
Your lab folder contains your notes, your scripts, your configurations, and your toolkit log. If your computer fails, you lose all of it. Back it up once a month. The simplest method is to copy the entire ~/cybersec-lab folder to a USB drive or to a cloud storage service.

Part 3: Quarterly documentation review.
Every three months, open your toolkit log and update it. Add any new tools. Remove any tools you no longer use. Update version numbers. This takes 15 minutes and it is the difference between a toolkit that works and a toolkit that is a mystery.

Part 4: Annual refresh.
Once a year, consider a full refresh. Reinstall the operating system. Reinstall the tools. Rebuild the lab folder. This is what professionals do, and it is the reason their tools always work. It is not because they are more skilled. It is because they maintain what they build.

Part 9 — Attack and Defence View

Let us now look at your toolkit from the perspective of the attacker and the defender, because the same tool can be used for both.

Nmap is used by attackers to find targets. It is used by defenders to find their own vulnerabilities. The same command nmap -sV 192.168.1.1 is used by both sides.

Wireshark is used by attackers to steal passwords from unencrypted networks. It is used by defenders to investigate incidents and find malicious traffic.

Python is used by attackers to write malware. It is used by defenders to write detection tools and automate response.

The toolkit is neutral. It is a set of capabilities. What makes it good or bad is who is holding it and what they use it for. This is the central ethical lesson of this field, and it is why this course exists. You are learning to use these tools for defence. Never forget that the same skills can be used for harm, and always choose the side you want to be on.

Part 10 — Common Mistakes Beginners Make

Mistake 1: Installing tools and then never using them. A tool you do not use is a tool you will forget. Use nmap at least once a week. Write at least one Python script a month. Practice is what turns knowledge into skill.

Mistake 2: Installing the wrong version. Many tools have multiple versions. Install the latest stable version, not the beta, not the old version. Betas are unstable. Old versions have known vulnerabilities.

Mistake 3: Not reading the error messages. When a tool does not work, the error message is telling you what is wrong. Read it carefully. It is the most useful information you have. Beginners ignore error messages and then spend an hour guessing. Professionals read error messages and fix the problem in minutes.

Mistake 4: Not documenting what you did. Six months from now you will install a tool and forget how you installed it. Write down the steps. Save the commands. Keep the toolkit log. Your future self will thank you.

Mistake 5: Treating the toolkit as finished. It is never finished. New tools appear. New versions are released. New problems require new skills. The toolkit is a living thing, and the day you stop adding to it is the day you stop growing as a professional.

Part 13 — Summary and Glossary

Here is what we covered.

The toolkit has six layers: operating system, terminal, Python, code editor, security tools, and the lab folder. The core security tools are nmap (network scanning), Wireshark and tshark (network analysis), VS Code (code editor), and Git (version control).

The maintenance plan has four parts: weekly updates, monthly backups, quarterly documentation review, and annual refresh. A toolkit that is not maintained is a liability, not an asset.

Glossary of 8 terms:

Terminal — a text-based interface for communicating with the computer.
